API & Documentation

Fetch newsletter articles as complete pages, take part in the community, and automate Gantt projects with a personal access token.

Every endpoint below accepts a personal access token from Profile → API access tokens.

Quick start

Make your first authenticated request in three steps. Replace the origin with your site’s address.

  1. 1

    Create a token

    Open Profile → API access tokens, name the token, and pick Newsletter & community with Read only or Read and write access. Tokens expire after 1–365 days.

  2. 2

    Store it safely

    The token is shown once. Keep it in an environment variable such as NEWSLETTER_API_TOKEN, never in source control.

  3. 3

    Call the API

    Send Authorization: Bearer <token> with each request. Responses are JSON, except complete article pages, which are HTML.

curl -fsS -H "Authorization: Bearer $NEWSLETTER_API_TOKEN" \
  "$NEWSLETTER_ORIGIN/api/v1/newsletters?q=release&perPage=10"
curl -fsS -H "Authorization: Bearer $NEWSLETTER_API_TOKEN" \
  "$NEWSLETTER_ORIGIN/api/v1/newsletters/$ARTICLE_ID/page" \
  -o article.html
curl -fsS -H "Authorization: Bearer $NEWSLETTER_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"body":"A post from my integration","clientId":"my-post-001"}' \
  "$NEWSLETTER_ORIGIN/api/community/posts"

API FAQs

Tokens, access, and responses.

Use a Newsletter & community token for articles and the community. Managers and administrators can also create a Gantt token for the Gantt API. Each token works only with its own scope.

Read only covers articles and every community GET route. Read and write adds posting, editing, interactions, uploads, profile updates, and reports. Choose the narrowest access your integration needs.

You choose an expiry between 1 and 365 days when you create it; the default is 90. Revoke a token at any time from Profile → API access tokens. Revocation takes effect on the next request.

401 means the token is missing, invalid, expired, or revoked. 403 means the token has the wrong scope or read-only access for a write. Article routes return 404 for unpublished articles.

Newsletter lists use page and perPage. Pages start at 1; page size defaults to 50, up to 100. Community lists return hasMore and cursor. Pass the cursor as ?cursor=… with the original filters to get the next page.

The page response includes a sandbox policy that disables scripts and interactive embeds. Keep that policy when you serve the document. Resolve root-relative images and file links against the newsletter site when you show a local copy.

Community FAQs

Acting in the community through the API.

Requests act as the token owner with member permissions. Posts, likes, and follows appear under that account. Moderation is not available through tokens; it requires a moderator’s website session.

Send a clientId with POST /api/community/posts and reuse the same value when you retry. The community recognizes the repeat and returns the original post.

Like, repost, bookmark, follow, block, and RSVP are toggles. Repeating the request reverses the previous action, so check the current state before you send it again.

Upload each file as multipart file to POST /api/community/media, then include the returned IDs in the post’s mediaIds.
