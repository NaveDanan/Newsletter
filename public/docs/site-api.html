Newsletter & community API

Fetch published articles and use the community from scripts or integrations.

All API docs · Authentication · Newsletters · Community · Gantt API

Authentication

Open Profile → API access tokens and create a Newsletter & community token. Choose Read only for article retrieval and community reads, or Read and write for community actions. Copy the token when it appears. Revoke it from the same screen to end access.

Use your site’s origin and send the token in the header on every authenticated request. Community requests act as the token owner with member permissions. Moderation requires a moderator’s website session.

Authorization: Bearer <token>

A missing credential on a protected endpoint, or an invalid, expired, or revoked token, returns 401. A token with the wrong scope or insufficient write access returns 403 on routes that accept personal tokens.

Newsletters

Method and pathResponse
GET /api/v1/newslettersSummaries with page, perPage, totalItems, totalPages, and items. Supports q for full-text search and feed=latest|top|discussions|bookmarks. Pages start at 1. Page size defaults to 50 and is capped at 100.
GET /api/v1/newsletters/{id}Article metadata, complete article body in content (HTML), and presentation and preview file links.
GET /api/v1/newsletters/{id}/pageA complete text/html article document with title, byline, cover, formatted body, and presentation links. The document disables scripts and interactive embeds. Page and JSON detail requests return 404 for unpublished articles.

Use pagePath from the list or detail response to fetch the HTML document. The response includes a sandbox policy. Preserve that policy when serving the document, and resolve root-relative images and file links against the newsletter site when displaying a local copy.

curl -fsS -H "Authorization: Bearer $NEWSLETTER_API_TOKEN" \
  "$NEWSLETTER_ORIGIN/api/v1/newsletters?q=release&perPage=10"

curl -fsS -H "Authorization: Bearer $NEWSLETTER_API_TOKEN" \
  "$NEWSLETTER_ORIGIN/api/v1/newsletters/$ARTICLE_ID/page" -o article.html

Community

Prefix these paths with /api/community. Paginated lists include items, hasMore, and cursor. Pass the returned cursor as ?cursor=... for the next page, alongside the original filters. Thread responses put the page’s replies in replies.

Method and pathAction
GET /feed?tab=latestRead the feed. Tabs are latest, for-you, and following.
GET /posts/{id}Read a post, its ancestors, and a page of replies.
GET /search?q={term}&type=posts
GET /hashtags/{tag}
GET /trends		Find posts, people, or hashtags. Search types are posts, people, and hashtags.
GET /me
GET /profiles/{handle}
GET /profiles/{handle}/{posts|followers|following}		Read the signed-in member’s profile, public profiles, posts, and connections. Handles omit the leading @.
GET /bookmarks
GET /notifications		Read the token owner’s bookmarks or notifications.
POST /postsCreate a post with body. Pass parentId to reply or quotedPostId to quote. Reuse the same clientId when retrying post creation. Link cards can reuse cached previews.
PATCH /posts/{id}
DELETE /posts/{id}		Edit or delete the token owner’s post.
POST /posts/{id}/{like|repost|bookmark}
POST /profiles/{handle}/{follow|block}		Toggle the interaction. A repeated request reverses the prior action.
POST /posts/{id}/vote
POST /posts/{id}/rsvp		Vote with {"optionId":"…"}, or toggle attendance for an event with an empty body.
POST /media
PATCH /me		Upload a multipart file and include the returned ID in the post’s mediaIds. Update profile fields such as displayName and bio through /me.
POST /notifications/read
POST /reports		Mark notifications read with {"ids":[…]}, or pass an empty array to mark all read. Report a post with postId or an account with handle, plus a reason and optional details.
 
curl -fsS -H "Authorization: Bearer $NEWSLETTER_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"body":"A post from my integration","clientId":"my-post-001"}' \
  "$NEWSLETTER_ORIGIN/api/community/posts"
