Newsletter & Project API Documentation

Developer guide and API endpoint references for custom PocketBase hook implementations.

Overview & Architecture

Welcome to the API Wiki. This documentation outlines the hook-based custom API routes added to PocketBase for managing newsletters and complex project Gantt workflows without modifying underlying collection schemas.

Select an endpoint or topic from the sidebar to view detailed parameters, validation constraints, schemas, and usage examples.

System Restrictions & Rules Quick-View

All endpoints must rigidly adhere to the non-breaking database requirements rules established in the planning lifecycle:

  • Immutable Fields: projects.gantt JSON structure and newsletters native attributes remain strictly locked.
  • Embedded Hierarchies: Subtasks must continuously leverage the indentLevel metadata flags.
  • Milestone Enforcements: Automatic assignment of milestone: true and forced durationDays: 0.

Implementation & Testing

Implemented Routes are registered from pb_hooks/main.pb.js through pb_hooks/lib/api-manager.js. Frontend wrappers in src/lib/pocketbase/newsletters.ts and src/lib/pocketbase/projects.ts call the custom API routes where useful.

Verification commands run:

node scripts/test-api-manager.cjs
npm run build

The helper test validates route-independent behavior: accepted statuses, rejected unknown statuses, workday task date normalization, milestone duration, subtask indentation, predecessor validation, deletion cleanup, newsletter role rules, project access rules, and project payload normalization.

Auth & Validation

  • Newsletter create: author, manager, general_manager, and admin.
  • Newsletter edit: admin can edit all records; other allowed roles can edit records where createdById matches the authenticated user.
  • Newsletter delete: admin only.
  • Newsletter public access: unauthenticated users can list or fetch only published newsletters.
  • Project access and mutation: authenticated admin, general_manager, project createdBy, or users listed in allowedUserIds.
  • Status validation: project/task statuses are pending, in-progress, completed, and delayed; newsletter statuses are draft and published.
  • Task validation: task dates are normalized to workdays, duration/progress values are clamped, milestones force zero duration, missing/self predecessor references are rejected, and duplicate task IDs are rejected.

GET/api/newsletters

Lists newsletters. Query params: status, page, perPage, and sort. Public callers only receive published items; authenticated authors can also see their own drafts; admins can see all.

curl "$PB_URL/api/newsletters?status=published&page=1&perPage=20&sort=-created"

POST/api/newsletters

Creates a newsletter using existing collection fields. Requires an allowed authoring role and sets createdById from the authenticated user on new records.

curl -X POST "$PB_URL/api/newsletters" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"title":"API update","subtitle":"","content":"<p>Hello</p>","author":"Team","coverImage":"","tags":[],"status":"draft"}'

GET/api/newsletters/:id

Fetches one newsletter. Draft records require edit permission; published records are public.

curl "$PB_URL/api/newsletters/$NEWSLETTER_ID"

PATCH/api/newsletters/:id

Updates editable newsletter fields and rejects unknown newsletter statuses.

curl -X PATCH "$PB_URL/api/newsletters/$NEWSLETTER_ID" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"title":"Updated title","status":"draft"}'

DEL/api/newsletters/:id

Deletes a newsletter. Requires admin.

curl -X DELETE "$PB_URL/api/newsletters/$NEWSLETTER_ID" \
  -H "Authorization: Bearer $ADMIN_TOKEN"

POSTNewsletter Status Actions

/api/newsletters/:id/make-public sets status to published. /api/newsletters/:id/make-draft sets status to draft. Both require newsletter edit permission.

curl -X POST "$PB_URL/api/newsletters/$NEWSLETTER_ID/make-public" -H "Authorization: Bearer $TOKEN"
curl -X POST "$PB_URL/api/newsletters/$NEWSLETTER_ID/make-draft" -H "Authorization: Bearer $TOKEN"

Project Management Routes

RouteBehaviorCommand
GET /api/projects Lists projects visible to the authenticated user. curl "$PB_URL/api/projects" -H "Authorization: Bearer $TOKEN"
POST /api/projects Creates a project with normalized empty gantt, default pending status, and createdBy from auth. curl -X POST "$PB_URL/api/projects" -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"title":"Roadmap","description":"","department":"","devision":"","field":""}'
GET /api/projects/:projectId Fetches one accessible project. curl "$PB_URL/api/projects/$PROJECT_ID" -H "Authorization: Bearer $TOKEN"
PATCH /api/projects/:projectId Updates project metadata, visibility, allowed users, status, or normalized gantt. curl -X PATCH "$PB_URL/api/projects/$PROJECT_ID" -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"isVisibleInGantt":true}'
PATCH /api/projects/:projectId/status Updates only project status. curl -X PATCH "$PB_URL/api/projects/$PROJECT_ID/status" -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"status":"in-progress"}'

Task Operations

RouteBehaviorCommand
GET /api/projects/:projectId/tasks Returns projects.gantt.tasks without schema changes. curl "$PB_URL/api/projects/$PROJECT_ID/tasks" -H "Authorization: Bearer $TOKEN"
POST /api/projects/:projectId/tasks Adds a root task with indentLevel: 0. curl -X POST "$PB_URL/api/projects/$PROJECT_ID/tasks" -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"name":"Build API","startDate":"2026-07-06","durationDays":3,"status":"pending"}'
PATCH /api/projects/:projectId/tasks/:taskId Updates a task or subtask, preserving the task ID and normalized fields. curl -X PATCH "$PB_URL/api/projects/$PROJECT_ID/tasks/$TASK_ID" -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"progress":50}'
PATCH /api/projects/:projectId/tasks/:taskId/status Updates only task status; completed also sets progress to 100. curl -X PATCH "$PB_URL/api/projects/$PROJECT_ID/tasks/$TASK_ID/status" -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"status":"completed"}'
DELETE /api/projects/:projectId/tasks/:taskId Deletes a task and descendant subtasks, then removes deleted IDs from remaining predecessorIds. curl -X DELETE "$PB_URL/api/projects/$PROJECT_ID/tasks/$TASK_ID" -H "Authorization: Bearer $TOKEN"

Subtask Operations

Subtasks are represented only with indentLevel. Creating a subtask sets indentLevel to the parent task's level plus one.

curl "$PB_URL/api/projects/$PROJECT_ID/tasks/$TASK_ID/subtasks" -H "Authorization: Bearer $TOKEN"
curl -X POST "$PB_URL/api/projects/$PROJECT_ID/tasks/$TASK_ID/subtasks" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"Write tests","startDate":"2026-07-06","durationDays":1,"status":"pending"}'

Milestones

Milestones are stored as tasks with milestone: true and durationDays: 0.

curl "$PB_URL/api/projects/$PROJECT_ID/milestones" -H "Authorization: Bearer $TOKEN"
curl -X POST "$PB_URL/api/projects/$PROJECT_ID/milestones" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"Launch","startDate":"2026-07-06","status":"pending"}'

Helpers

The registered helper module exports these functions for route wiring and tests: registerApiManager, normalizeTask, normalizeGantt, getDescendantIds, listDirectSubtasks, cleanupTaskReferences, buildNewsletterPayload, buildProjectPayload, canCreateNewsletter, canEditNewsletter, canDeleteNewsletter, canReadNewsletter, and canAccessProject.
