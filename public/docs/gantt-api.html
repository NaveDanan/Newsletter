Gantt API

Read and change Gantt tasks, milestones, subtasks, and project progress from scripts, integrations, and AI agents. Every request is authenticated with a personal access token that you create in your profile.

Base URL: https://your-site Auth: Authorization: Bearer <token> Format: JSON Applies to Newsletter 1.0.30 and later
Who can create tokens
Managers, general managers, and administrators can choose the Gantt scope under Profile → API access tokens. For articles and community interactions, see the Newsletter and community API.
Token format
nlpat_ followed by 48 random characters. Only a SHA-256 hash is stored.
Access levels
Read: GET requests only. Write: GET plus the write requests listed below.
Lifetime
1 to 365 days. The profile offers 30, 90, or 365 days; the API default is 90.
Limit
20 tokens per account, counting expired tokens. Revoke unused tokens to free a slot.
Scope
Gantt tasks, subtasks, milestones, progress, and project status for projects you can access. Nothing else.
Working calendar
Sunday to Thursday. Friday and Saturday are rest days, so durations and end dates skip them.

For AI agents

  1. Base URL. Use the site origin shown above. Every path in this document starts with /api.
  2. Authentication. Send Authorization: Bearer <token> on every request. Read the token from an environment variable such as NEWSLETTER_API_TOKEN. Never place it in a URL, query string, log, or chat message.
  3. Task identity. Identify a task with the pair projectId + taskId. Task ids are unique within a project, not across projects.
  4. Check access first. A read token gets 403 on any non-GET request. Ask the user for a write token before you attempt writes.
  5. Use the manifest. The JSON in the manifest section lists every allowed route, its access level, its body fields, and its success status.
  6. Prefer PATCH for changes. POST creates records. PATCH changes existing ones. DELETE removes a task and all of its subtasks.
  7. Handle errors deliberately. On 401, the token is invalid, revoked, or expired: stop and ask the user for a new token rather than retrying. On 403, the request is outside the token's scope or the owner's role: do not try other routes to get around it.
  8. Verify after a batch. After several writes, call GET /api/projects/{projectId}/progress to confirm the calculated state.
  9. Avoid retries that duplicate work. A POST that returns a network error may have succeeded. List the tasks again before creating a task a second time.

Overview

Each project holds an ordered list of Gantt tasks. A task can be a regular task, a milestone, or a subtask nested under another task. The API works on that list directly; the website shows the same data as a timeline.

ConceptMeaning
ProjectA container for tasks, with its own status and sharing settings. Its progress is calculated from its tasks.
TaskA unit of work with a start date, a duration in working days, a status, and a progress percentage.
MilestoneA zero-duration marker on a single date. It has no effect on calculated progress.
SubtaskA task nested under a parent. Deleting a parent deletes its subtasks.
PredecessorA task that must finish before another one starts. Circular dependencies are rejected.
ProgressA calculated percentage for the whole project, weighted by task duration.

Create and manage tokens

Create a token

  1. Sign in to the website with your normal account.
  2. Open Profile → API access tokens. If you do not see this section, your role does not allow tokens (see Troubleshooting).
  3. Enter a name of up to 80 characters so you can recognise the token later, such as Weekly status script.
  4. Choose Read and write or Read only.
  5. Choose an expiry of 30, 90, or 365 days, then select Create token.
  6. Copy the token immediately. It is displayed once and cannot be recovered later.
The full token is shown once.

If you lose it, revoke it and create a new one. The site stores only a hash of the secret, so it cannot show the token again.

Access levels

AccessAllowed requestsTypical use
readGET requests within scopeDashboards, reports, sync checks
writeGET plus the POST, PATCH, and DELETE requests in Permissions and scopeAutomation that edits schedules or progress

Revoke a token

Select Revoke on the token row, then confirm. Revocation takes effect immediately. The token is then rejected with 401, and any script still using it stops working.

Lifetime and limits

  • The API accepts any whole number of days from 1 to 365. The profile offers 30, 90, and 365, with 90 selected by default.
  • Expired tokens remain in the list until you revoke them, and they count toward the limit of 20 per account.
  • Signing out of the website does not revoke tokens. They keep working until they expire or you revoke them.
  • Token management requires a normal signed-in website session. A token cannot create, list, or revoke tokens.

Authentication

Send the token in the Authorization header with the Bearer scheme. Do not put it in the URL.

Authorization: Bearer nlpat_<48 characters>

The same header works on the frontend origin and on the direct PocketBase origin, because both route to the same API.

OriginUse
https://your-siteRecommended. The website proxy used by the browser.
http://10.40.240.3:32290Direct PocketBase API on the current MMEMS deployment.
Keep tokens out of URLs and logs.

Query strings are recorded by proxies and access logs. Store the token in an environment variable or a secret manager. Use HTTPS wherever the site is configured for it.

Permissions and scope

A token is limited in two ways. First, it can reach only the routes in the table below, whatever the owner's role. Second, it sees only the projects the owner can access right now. Access is evaluated on every request, so a change to the owner's role takes effect immediately.

MethodRouteAccess needed
GET/api/projects, /api/projects/tasks, /api/projects/{projectId}, /api/projects/{projectId}/tasks, /api/projects/{projectId}/tasks/{taskId}/subtasks, /api/projects/{projectId}/milestones, /api/projects/{projectId}/progressread or write
POST/api/projects/{projectId}/tasks, /api/projects/{projectId}/tasks/{taskId}/subtasks, /api/projects/{projectId}/milestoneswrite
PATCH/api/projects/{projectId}/tasks/{taskId}, /api/projects/{projectId}/tasks/{taskId}/status, /api/projects/{projectId}/progress, /api/projects/{projectId}/statuswrite
DELETE/api/projects/{projectId}/tasks/{taskId}write

Any other route returns 403. Examples include creating or editing a project (POST /api/projects, PATCH /api/projects/{projectId}), sharing settings, newsletters, community posts, and every token route. There is no single-task GET route: to read one task, fetch the project's task list and select the item by id.

Who sees which projects

  • Managers see the projects they own and the projects shared with them.
  • General managers and administrators see all projects.
  • An owner who is deleted, or whose role falls below manager, loses access for all of their tokens.

Data model

Task object

FieldTypeMeaning
idstringUnique within its project. Generated by the server when omitted on create. Duplicate ids make later updates ambiguous, so let the server generate them where you can.
namestringDisplay name.
startDateYYYY-MM-DDFirst working day. Omitting it uses today's working day. A date that falls on Friday or Saturday moves forward to Sunday.
durationDaysinteger ≥ 1Length in working days, Sunday to Thursday. Values are rounded and clamped to at least 1 for regular tasks. Milestones always have 0.
endDateYYYY-MM-DDCalculated from startDate and durationDays. Any value you send is replaced.
statusenumpending, in-progress, completed, or delayed. Any other value returns 400.
progressinteger 0–100Stored percentage. Values are rounded and clamped to the range.
predecessorIdsstring[]Ids of tasks in the same project that must finish first. Unknown references are dropped. A cycle returns 400.
resourceIdstring or nullOptional assignment to a resource used by the timeline.
indentLevelinteger ≥ 0Depth in the hierarchy. New top-level tasks start at 0. Subtask creation sets this for you.
milestonebooleantrue for milestones. Create them with the milestones endpoint rather than setting this flag yourself.

The all-tasks endpoint adds two fields to every task: projectId and projectTitle. Always send both the project id and the task id when you change a task.

Task status

ValueMeaningProgress contribution
pendingNot started0%
in-progressUnder wayStored progress if above 0, otherwise 50%
completedFinished100%
delayedBehind schedule0%

Dates and working days

Durations and end dates count only working days. For example, a task starting on Sunday 15 November 2026 with durationDays: 2 ends on Monday 16 November 2026. A task starting on a Thursday with durationDays: 2 ends on the following Sunday, because Friday and Saturday are skipped.

Endpoint reference

All bodies are JSON and need Content-Type: application/json. Examples use the shell variables $BASE_URL and $NEWSLETTER_API_TOKEN. Values such as <projectId> are placeholders. Ids in responses are examples; the server generates the real ones.

Projects

GET/api/projectsread

List accessible projects

Returns every project the token owner can access, including each project's Gantt data.

Response · 200
{ "items": [ { "id": "<projectId>", "title": "Launch plan", "status": "in-progress", ... } ] }
GET/api/projects/{projectId}read

Get one project

Returns one project. Returns 403 if the owner cannot access it and 404 if it does not exist.

GET/api/projects/tasksread

List all tasks across accessible projects

The most efficient way to read everything in one call. Each task includes projectId and projectTitle.

Response · 200
{
  "items": [ { "id": "...", "projectId": "...", "projectTitle": "Launch plan", "name": "...", "status": "pending", ... } ],
  "totalItems": 42,
  "projectCount": 3
}
Example
curl -H "Authorization: Bearer $NEWSLETTER_API_TOKEN" \
  "$BASE_URL/api/projects/tasks"

Tasks

GET/api/projects/{projectId}/tasksread

List a project's tasks

Returns every task in one project, in stored order, including subtasks.

Response · 200
{ "items": [ { "id": "...", "name": "...", "startDate": "...", ... } ] }
POST/api/projects/{projectId}/taskswrite

Add a task

Adds a top-level task at the end of the project's list.

Body fields
FieldRequiredNotes
nameRecommendedDisplay name.
startDateNoYYYY-MM-DD. Defaults to today's working day.
durationDaysNoWorking days. Defaults to 1.
statusNoDefaults to pending.
progressNo0–100. Defaults to 0.
predecessorIdsNoTask ids in the same project.
resourceIdNoResource assignment.
idNoLeave out so the server generates it.
Example
curl -X POST -H "Authorization: Bearer $NEWSLETTER_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"Prepare release","startDate":"2026-11-15","durationDays":2,"status":"pending"}' \
  "$BASE_URL/api/projects/<projectId>/tasks"
Response · 201
{
  "id": "<taskId>",
  "name": "Prepare release",
  "startDate": "2026-11-15",
  "endDate": "2026-11-16",
  "durationDays": 2,
  "progress": 0,
  "status": "pending",
  "indentLevel": 0,
  "predecessorIds": [],
  "resourceId": null,
  "milestone": false
}
PATCH/api/projects/{projectId}/tasks/{taskId}write

Update a task

Changes only the fields you send. Other fields keep their current values, and endDate is recalculated from the new start and duration. Send status changes through the status endpoint below, which also sets progress to 100 for completed tasks.

Example
curl -X PATCH -H "Authorization: Bearer $NEWSLETTER_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"durationDays":3,"predecessorIds":["<otherTaskId>"]}' \
  "$BASE_URL/api/projects/<projectId>/tasks/<taskId>"
Response · 200

The updated task object.

PATCH/api/projects/{projectId}/tasks/{taskId}/statuswrite

Change a task's status

Sets status. Setting completed also sets progress to 100.

Body
{ "status": "completed" }
Response · 200

The updated task object.

DELETE/api/projects/{projectId}/tasks/{taskId}write

Remove a task and its subtasks

Deletes the task and every descendant subtask. Predecessor references to any deleted task are removed from the remaining tasks. This cannot be undone through the API.

Response · 200
{ "status": "deleted", "deletedTaskIds": ["<taskId>", "<childTaskId>"] }

Subtasks

GET/api/projects/{projectId}/tasks/{taskId}/subtasksread

List direct subtasks

Returns the immediate children of a task. Grandchildren are not included; query them through their own parent.

Response · 200
{ "items": [ { "id": "...", "indentLevel": 1, ... } ] }
POST/api/projects/{projectId}/tasks/{taskId}/subtaskswrite

Add a subtask

Inserts the new task directly after the parent's existing subtree, one level deeper. Accepts the same body fields as Add a task.

Response · 201

The new subtask object, with indentLevel set to the parent's level plus one.

Milestones

GET/api/projects/{projectId}/milestonesread

List milestones

Response · 200
{ "items": [ { "id": "...", "name": "Go live", "milestone": true, "durationDays": 0, ... } ] }

Add a milestone

Creates a zero-duration milestone on startDate. Accepts name, startDate, status, and predecessorIds. Any durationDays you send is ignored.

The new milestone object.

Progress and status

GET/api/projects/{projectId}/progressread

Read calculated progress

Returns the project's status and its calculated progress. Progress cannot be set directly; see Progress calculation.

Response · 200
{
  "projectId": "<projectId>",
  "status": "in-progress",
  "progress": 60,
  "taskCount": 4,
  "completedTaskCount": 2,
  "lastEditedAt": "2026-11-15T10:00:00.000Z"
}
PATCH/api/projects/{projectId}/progresswrite

Update several task percentages atomically

Applies a list of task updates and, optionally, a new project status in one transaction. If any task id is missing or any value is invalid, nothing is saved.

Body
FieldNotes
statusOptional project status: pending, in-progress, completed, or delayed.
tasksOptional array of { "id", "status"?, "progress"? }. Ids must be unique within the request. Only id, status, and progress are accepted per item.

At least one of status or a non-empty tasks array is required.

Example
curl -X PATCH -H "Authorization: Bearer $NEWSLETTER_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"status":"in-progress","tasks":[{"id":"<taskId>","progress":60}]}' \
  "$BASE_URL/api/projects/<projectId>/progress"
Response · 200

The same progress object as the GET endpoint, reflecting the saved state.

PATCH/api/projects/{projectId}/statuswrite

Change the project's status

Sets the project status. This does not change task progress.

Body
{ "status": "delayed" }
Response · 200

The updated project object.

Progress calculation

Project progress is derived from tasks. It is not a separate value you can edit, so the same tasks always produce the same percentage, whether you read it on the website or through the API.

weight(task)   = 0 for milestones, otherwise max(1, durationDays)
percent(task)  = 100 if completed
               = stored progress if in-progress and above 0, otherwise 50 when in-progress
               = 0 otherwise                                  (pending, delayed)

progress       = round( sum(weight × percent) / sum(weight) )
               = 0 when the project has no tasks

To change progress, update task percentages through PATCH progress. When you send a percentage without a status, the status is derived: 100 becomes completed, any value above 0 becomes in-progress, and 0 becomes pending.

Errors

Errors return JSON with a message and a status code.

StatusWhenExample message
400Invalid input or a rule violationTask predecessor references create a circular dependency. · Only task status and progress can be updated here. · Task progress must be a number between 0 and 100. · Unknown task status.
401Token missing, malformed, revoked, or expiredInvalid API token. · API token has expired.
403Read-only token on a write, a route outside the token's scope, the owner's role no longer allows it, or the project is not accessibleThis API token has read-only access. · This API token is limited to Gantt tasks and project progress. · The token owner no longer has manager access.
404Project or task does not existTask not found.

Creating a token can also return 400 for a missing name, an invalid access value, an expiry outside 1 to 365 days, or a 21st token: Revoke an existing token before creating more than 20 tokens.

Examples

Set the environment

export BASE_URL="https://your-site"
export NEWSLETTER_API_TOKEN="nlpat_<paste your token>"

List every task as a table

curl -s -H "Authorization: Bearer $NEWSLETTER_API_TOKEN" \
  "$BASE_URL/api/projects/tasks" \
  | jq -r '.items[] | [.projectTitle, .name, .status, .progress] | @tsv'

Add a task that depends on another

curl -X POST -H "Authorization: Bearer $NEWSLETTER_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"QA sign-off","startDate":"2026-11-22","durationDays":3,"predecessorIds":["<releaseTaskId>"]}' \
  "$BASE_URL/api/projects/<projectId>/tasks"

Mark a task complete and check the project

curl -X PATCH -H "Authorization: Bearer $NEWSLETTER_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"status":"completed"}' \
  "$BASE_URL/api/projects/<projectId>/tasks/<taskId>/status"

curl -s -H "Authorization: Bearer $NEWSLETTER_API_TOKEN" \
  "$BASE_URL/api/projects/<projectId>/progress"

Python (standard library only)

import json
import os
import urllib.request

BASE_URL = os.environ["BASE_URL"]
TOKEN = os.environ["NEWSLETTER_API_TOKEN"]

def call(method, path, body=None):
    data = json.dumps(body).encode() if body is not None else None
    request = urllib.request.Request(
        BASE_URL + path,
        data=data,
        method=method,
        headers={
            "Authorization": f"Bearer {TOKEN}",
            "Content-Type": "application/json",
        },
    )
    # urllib raises HTTPError for 4xx/5xx responses; catch it to read the message.
    with urllib.request.urlopen(request) as response:
        return json.load(response)

tasks = call("GET", "/api/projects/tasks")["items"]
open_tasks = [t for t in tasks if t["status"] != "completed"]
print(f"{len(open_tasks)} of {len(tasks)} tasks are not completed")

Troubleshooting

I don't see "API access tokens" in my profile

The section is shown only to managers, general managers, and administrators. Signed-in members without a manager role will not see it. Ask an administrator to check your role.

My script gets 401 Invalid API token.

The token was revoked, deleted, or mistyped. Check that the header is exactly Authorization: Bearer nlpat_… with no line breaks or extra spaces. If the token is correct, create a new one.

My script gets 401 API token has expired.

The token passed its expiry date. Create a new one, choosing a longer lifetime if the integration needs it.

Reads work but writes return 403

The token is read only. Access cannot be changed on an existing token, so revoke it and create a new one with Read and write.

I lost the token

The full token is shown only once. Revoke the lost token so it cannot be used, then create a new one and store it in your secret manager.

I can't create a token: the limit is reached

Each account can hold 20 tokens, including expired ones. Revoke unused or expired tokens to free a slot.

Deleting a task removed more than I expected

Deleting a task also deletes all of its subtasks, and removes it from the predecessor lists of other tasks. The response lists every deleted id in deletedTaskIds. Check the list before deleting parents.
